A read-only MCP server for Apple Mail

Importin reads what Mail.app already keeps on your Mac and gives an AI agent six tools to find and read it, S/MIME-encrypted messages included. It cannot send, move, flag or delete mail.

DownloadA zip for Apple Silicon or for Intel. The binary is not notarised by Apple, so macOS refuses it once; one command clears that (Install), or build it from source. Source on GitHub.

In the cell

A nuclear pore passes about a thousand molecules a second, and a human nucleus has a few thousand of them. Each pore is one of the largest machines in the cell: around thirty kinds of protein, each present in multiples of eight, which is why the ring has eight subunits.

An importin is a carrier. It reads a short address tag on its cargo, the nuclear localisation signal, often a run of lysines and arginines such as PKKKRKV (for that classic tag, importin‑α reads and importin‑β carries). Bound to the cargo, it slips through the pore's meshwork of disordered proteins, which turns away anything much above 40 kDa that has no carrier, and lets go inside when it meets RanGTP, the nucleus's own signal that the cargo has arrived. The importin goes back out alone for the next one; exportins carry cargo the other way.

How it works

Mail’s own files
The Envelope Index, Mail’s SQLite database, answers searches by header; the .emlx message files, and the attachments Mail stores beside them, give bodies and attachments. Both are read in ~/Library/Mail, where Mail keeps them: no index to build, no watcher, no network.
Six tools
Find messages by sender, recipient, Cc, subject, date, mailbox or words in the body; read a message with its To, Cc and Bcc, its thread, or an attachment as text; list mailboxes and accounts.
S/MIME
Encrypted messages are decrypted per request, by default with the key in your keychain; the plaintext lives in the response only and is never written to disk.
Read-only
No code path sends, moves, flags or deletes mail, and a test reads the source to keep it that way.

The six tools

  • search

    Arguments
    query (words; all must match), scope = all (default) | subject | from | to | cc | participant | body, after/before (RFC 3339 or YYYY-MM-DD = local midnight), mailbox, account, from (substrings), unread, flagged, limit 1–200 (25), offset
    Returns
    hits, newest first: id, dates, subject, from/to/cc, mailbox, account, read, flagged, encrypted, signed, has_attachments, snippet; truncated

  • get_email

    Arguments
    id, max_chars 500–200 000 (20 000), html (also return the raw HTML part)
    Returns
    headers with to/cc/bcc/reply_to, message_id, body and body_source (plain, html, none), encryption, attachments with their state

  • get_thread

    Arguments
    id, limit 1–200 (50)
    Returns
    the newest limit messages of the conversation, oldest first, in the search hit shape; truncated

  • attachment_text

    Arguments
    id, filename or index as get_email lists them, max_chars 500–100 000 (20 000)
    Returns
    text of PDF, Word (docx), Excel (xlsx, xlsb), PowerPoint (pptx), HTML and text attachments; other types get a one-line note

  • list_mailboxes

    Arguments
    account (substring, optional)
    Returns
    mailboxes with message and unread counts

  • list_accounts

    Arguments
    none
    Returns
    accounts with mailbox and message counts

The header scopes match case-insensitive substrings in the Envelope Index: all covers subject, sender, every recipient and Mail’s summary; participant covers sender, To, Cc and Bcc. scope: body reads the message files instead and needs a query: it scans the newest body_scan_max (500) messages that pass the other filters, received since after, by default the body_scan_days (90) days before before or before now. Encrypted bodies are never searched.

Deleted messages are left out of searches, threads and counts. Ids are good within a session only, since Mail renumbers rows when it rebuilds its index; message_id is durable.

S/MIME-encrypted and signed mail

  • Encrypted messages are decrypted per request. The plaintext lives in the response only and is never written to disk.
  • By default importin pipes the encrypted body to /usr/bin/security cms -D, which finds the private key among the identities of your keychain search list, normally the login keychain. The first time, macOS asks whether security may use the key: choose Always Allow. The grant belongs to Apple’s signed security, so it survives updates of importin.
  • Signatures are not verified: a signed message says signature: "not verified". An opaque signed message, a single smime.p7m, is unpacked, and its content is the body and the attachments.
  • For a key that is not in a macOS keychain, the openssl decryptor reads it from PEM files named in ~/.config/importin/config.toml. security cms does not support authEnveloped-data (AES-GCM), and importin says so; the openssl decryptor passes it on, a path that is untested.

Read-only by construction

  • Importin has no code path that sends, moves, flags or deletes mail, and no switch that adds one. It does not script Mail.app, and it opens the Envelope Index read-only.
  • A test keeps it that way: tests/readonly.rs reads every line under src/ and fails on any name of a write path, among them osascript, smtp, send_mail, move_message, delete_message, set_flag, fs::write, File::create and SQLite’s read-write and create flags. A second test fails unless every open_with_flags call in src/ passes SQLITE_OPEN_READ_ONLY.

Read-only is not private. What importin returns goes to your agent’s model; with a hosted model, it leaves the Mac. To keep an account from the agent, list it in exclude_accounts in ~/.config/importin/config.toml: an excluded account is invisible to every tool.

Install and connect

  1. Get the binary

    Each release carries importin-<tag>-<target>.zip for aarch64-apple-darwin (Apple Silicon) and x86_64-apple-darwin (Intel). Download it from the release page or with gh, which takes the latest release, unzip it, clear the quarantine flag and put it on your PATH:

    The quarantine step is there because the binary is not notarised: notarisation means Apple has scanned a build submitted under a paid developer account, and Importin has none. Without it, Gatekeeper refuses a downloaded binary (“cannot be opened because the developer cannot be verified”) until the quarantine flag that the browser or gh attached is removed; “No such xattr” means there was none. A binary you build yourself with cargo install never carries the flag.

    gh release download -R glia-org/importin -p '*-aarch64-apple-darwin.zip'
unzip importin-*-aarch64-apple-darwin.zip importin
xattr -d com.apple.quarantine importin
mkdir -p ~/.cargo/bin && mv importin ~/.cargo/bin/

    Or build it from a checkout of the source: cargo install --path . puts it in ~/.cargo/bin/importin. The snippets below assume that path; any absolute path works.

  2. Grant Full Disk Access

    ~/Library/Mail sits behind Full Disk Access, and macOS asks the app at the top of the process chain, not importin. Grant it to the app that launches your MCP host, your terminal app for opencode and Claude Code, Claude.app for Claude Desktop, in System Settings → Privacy & Security → Full Disk Access. Without it the server exits at startup with status 2 and says why on stderr.

  3. Add it to your MCP host

    importin speaks MCP on stdio. JSON configs are not passed through a shell, so write the path out in full there.

    opencode, in opencode.json; the key mail makes the tools appear as mail_*

    {
  "mcp": {
    "mail": {
      "type": "local",
      "command": ["/Users/you/.cargo/bin/importin"],
      "enabled": true
    }
  }
}

    Claude Code; the shell expands ~

    claude mcp add --scope user mail -- ~/.cargo/bin/importin

    Claude Desktop, in claude_desktop_config.json

    {
  "mcpServers": {
    "mail": {"command": "/Users/<you>/.cargo/bin/importin"}
  }
}

  4. Check the setup with importin doctor

    Run it from the app that will launch your host. It checks Full Disk Access, the store and its schema, how message files are found, the S/MIME identities in your keychain, a decrypt probe on the newest encrypted message, and timings. It exits with 0 when Full Disk Access is granted and the schema resolved, else 2. --json prints the same as JSON; --anon leaves out account names, exclusion patterns, paths and addresses.

    Run it once from a terminal to answer the keychain dialog while you are there: its probe waits 60 s, the server’s decryptor gives up after 10 s.

The name

The name is the carrier's: this program does the inbound half, reading the address on each message and carrying it in to the agent. There is no exportin in it.

The drawing at the top is such a pore, seen from the cytoplasm: eight subunits in a ring around the channel. It leaves out that in the cell the importin goes back out for the next cargo.
