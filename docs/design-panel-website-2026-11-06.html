0. What the site is for (write-back)

What it is for. One page for Importin, like the pages of Lemna and Glia: what it reads, what it can never do, how to install it and add it to an MCP host. glia-org publishes it on GitHub Pages; with H1 at https://glia-org.github.io/importin/, beside Lemna's at https://glia-org.github.io/lemna/.

assumed Who reads it. People choosing an MCP server for Apple Mail on a Mac, and people whose agent (opencode, Claude Code, Claude Desktop) should read their mail. Both decide on the same three things: what the server can reach, what it can never do, and what to paste where.

Fixed by the family. The glia site's rules 1–8 (glia.github.io/README.md), with Lemna's page as the nearest model: plain static files, no third-party requests, every claim true of the build, plain wording, nothing behind a switch, no real data, complete without JavaScript, the product's own look. Section 2 restates them for this page. Rule 8 (the product's own look) has no Importin equivalent yet: D2, D4 and D7 decide it.

Blocking fact

The page needs a public repository. GitHub Pages serves a site from a private repository only on a paid plan (Pro, Team, Enterprise). glia-org is on the free plan (gh api orgs/glia-org answers plan: free, checked 2026-11-06; HANDOFF.md also calls it a free-plan org), and glia-org/importin is private. So the page goes live only from a public repository: D6.

The same holds for the download. A reader without access to the private repository cannot fetch the release zips, and cargo install importin waits for the crates.io publish. Today the page could offer a stranger no way to install Importin.

Success looks like: on the first screen a reader learns what Importin reads and that it cannot write; in the install section, which line to paste for their host; the page passes tools/check.py, and nothing on it comes from a real mailbox.

1. Decisions

Every option has a short id. Pick one per decision with its radio button, or answer in the chat with one id per decision, for example A V2 P1 C1 S1 H1 M1 R2. D2 to D8 are worked out for direction A; for B or C they are re-cut.

D1

Direction: what the first screen is

Three ideas for the whole page, with the same content and the same rules. Each mockup is drawn in the D4 palette, so it follows this panel's light or dark appearance.

A

The pore

recommended
glia-org.github.io/importin/
Importin

A read-only MCP server for Apple Mail

It reads what Mail.app keeps on this Mac and gives an AI agent six tools to find and read messages, S/MIME-encrypted ones included. It cannot send, move, flag or delete mail.

Download v0.1.0Source on GitHub

What it does

  • Six tools: search, get_email, get_thread, attachment_text, list_mailboxes, list_accounts.
  • S/MIME decrypted per request by macOS's security cms.
  • A test greps the source for write paths.

The hero is a drawn nuclear pore, a ring in the nuclear envelope. Letters with an address tag are carried in through it, each by an importin, and released inside; nothing travels out. SVG with CSS motion; reduced motion shows a still. Below it, the page is the facts.

Strength
It is the name, drawn: the page explains “importin” without a paragraph. Traffic in one direction shows read-only without saying it twice. It is the family's one piece, like Lemna's demo and Glia's astrocytes.
Weakness
The most work: the drawing, its motion and its still. A metaphor needs one plain sentence beside it, or it reads as decoration. The biology is simplified: in the cell the importin itself goes back out; the drawing leaves that out.

Variant: the pore in section, with the nuclear envelope drawn as the rule between the hero and the facts, so that the facts sit inside. Answer A-section for it.

D3

The piece: one figure that is the product's own idea

One piece only, as on the other two pages. Whichever it is, it works without JavaScript and stands still under reduced motion.

P1

The pore, in motion

recommended with A

A ring of eight subunits, the nuclear pore's eightfold symmetry, seen from the cytoplasm. Each letter carries its address tag and lies in an importin, the arc under it. The letters move in, and at the centre each one is released into the nucleus below the pore. Nothing moves out. On the site this is inline SVG with CSS keyframes, no canvas and no script: this sketch is about 9 kB of markup and 5 kB of keyframes. A pause control is there for readers who keep motion on (WCAG 2.2.2 asks for one when motion runs longer than five seconds).

Strength
Says the name and read-only in one drawing. Light: no WebGL, no script. Its still is the mark (M1).
Weakness
Has to stay calm: four letters at most, slow, nothing that flashes. The arc and the tag need the caption to be read as importin and address tag.

Sections

What the page says, in order. Per family rule 4, each section is a headline and at most four points. The draft copy comes from the README and DESIGN.md; where it needs something they do not say yet, it is marked.

S1

Full: seven sections

recommended
  1. Lead. “A read-only MCP server for Apple Mail.”
    • It reads what Mail.app already keeps on this Mac, the Envelope Index and the .emlx files, and gives an AI agent six tools to find and read messages. It cannot send, move, flag or delete mail.
    • Links: the latest release, the source.
  2. The piece (P1), with one plain caption: “Importin reads the address tag on each message and carries it in. Nothing is carried out: it has no way to send, move, flag or delete.”
  3. What it does
    • Six tools. search by sender, recipient, Cc, subject, date and mailbox, or by words in the body; get_email with To, Cc and Bcc; get_thread; attachment_text for PDF, Word, Excel, PowerPoint, HTML and text; list_mailboxes; list_accounts.
    • S/MIME. Encrypted messages are decrypted per request by macOS's security cms with the identity in your login keychain. The plaintext lives in the reply only, never on disk. Signatures are not verified.
    • Read-only. No code path sends, moves, flags or deletes, and a test greps the source to keep it so. No index to build, no watcher, no network. Accounts in exclude_accounts are invisible to every tool. 186 tests run on a synthetic Mail store.
    • Speed, measured on 2026-11-04 on a Mac with Apple Silicon, macOS 26.5, on a store of ⟨size: Q4⟩ messages: opening the store 3 ms, a header search 2 ms, get_email under 1 ms; a body search read 192 messages in 91 ms.
  4. Install
    • Download the zip for Apple Silicon or Intel from the latest release (each v* tag carries both), unzip it, clear the quarantine flag (the binary is not notarised) and put importin on your PATH. Or build it from a checkout: cargo install --path .
    • Grant Full Disk Access to the app that launches your MCP host: your terminal app for opencode and Claude Code, Claude.app for Claude Desktop. Without it importin exits at startup and says why.
    • Add it to your host; all three are shown at once: 
      opencode, in opencode.json
{
  "mcp": {
    "mail": {
      "type": "local",
      "command": ["/Users/you/.cargo/bin/importin"],
      "enabled": true
    }
  }
}

Claude Code
claude mcp add --scope user mail -- ~/.cargo/bin/importin

Claude Desktop, in claude_desktop_config.json
(not in the README yet)
{
  "mcpServers": {
    "mail": {"command": "/Users/you/.cargo/bin/importin"}
  }
}
  5. Check the setup: importin doctor
    • A checklist: Full Disk Access, the store, the schema, how message files were found, S/MIME identities, a decrypt probe, timings.
    • Run it once from the app that launches your host. The first time, macOS asks whether security may use your key: choose Always Allow.
    • --anon leaves out account names, paths and addresses; --json prints the same as JSON.
    • Exit status 0 when Full Disk Access is granted and the schema resolved, else 2.
    ok   importin: 0.1.0
ok   full disk access: ok
ok   path sample: 20 sampled: 20 formula, 0 walk, 0 missing
ok   s/mime identities: 1
ok   decrypt probe (security): 50 ms
ok   time get_email: 1 ms
    Line format from src/doctor.rs; values illustrative. The site's sample would be printed by doctor on the test store.
  6. The name
    • Importin is a protein. Importin-α reads the nuclear localization signal, the address tag on a cargo protein; importin-β carries the cargo through the gated nuclear pore and releases it inside. Exportins carry the outbound traffic; this program has none.
  7. Footer. Apache-2.0. Literata by the Literata Project Authors, under the SIL Open Font License 1.1. No cookies, no analytics, no third-party requests.

2. Fixed, whatever the picks

The family's rules (glia's site README, rules 1–8), restated for this page. They go into the site README with the picks.

  • Plain static files in site/: no build step, no framework, no package manager.
  • No third-party requests. Fonts self-hosted with their licence text; no CDN, analytics, cookies or embeds; external URLs only as links. tools/check.py, adapted from glia's, enforces it, and also checks local references, unique ids, element nesting and the D4 contrast floors.
  • Every claim true of the build as released (v0.1.0 today). Numbers say where they were measured. What is not built or not published is not offered, such as cargo install importin; gaps are named, such as signatures that are not verified. No superlatives, no exclamation marks.
  • Plain and precise wording. Descriptive headlines; per section a headline and at most four points; no slogans; no text on how to use the page.
  • Nothing hidden behind a switch. All three host snippets are visible at once; depth lives in the linked README and DESIGN.md.
  • No real mail on the page. No message, address, mailbox name or count from the author's store. Examples are synthetic (Erika Muster, Max Mustermann, example.org, INBOX, dates in 2026), and replies are produced from the test store.
  • Complete without JavaScript. The piece is SVG and CSS; P2, if built, is radio buttons and CSS.
  • Reduced motion honoured. The piece stands still; a pause control serves everyone else.
  • Phones get one column, with 16 px gutters.
  • Licences in the footer: Apache-2.0 for the site and the code; the font's licence (Literata, SIL Open Font License 1.1), its text served beside the font.
